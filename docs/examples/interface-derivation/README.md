# Interface 分层推导（Phase 2）

对应 [design-refine-derivation.md](../../design-refine-derivation.md) §5。

| 文件 | 角色 |
|---|---|
| `std.nudo.js` | 共享模板（`positive` / `positive4`） |
| `lib.nudo.js` | **契约根**：手写 `add4 = fn({ x: positive }, positive4)` |
| `lib.js` | 干净源码：`add4(x) = add2(x+1)+1` |
| `add.js` | 下游导出：`add2(x) = x+2` |

## 下行

```
positive ──shift(1)──► add2 入参 ──shift(2)──► add2 返回 ──shift(1)──► add4 返回
```

## 固化下游

```bash
pnpm run contract --emit docs/examples/interface-derivation/lib.js --fn add2
# 旧动词 `nudo interface --emit` 已 deprecated → contract
```

生成 `add.nudo.js`（组合式，不展开；本仓库已提交该生成物，命令可幂等重跑）：

```js
// @generated by nudo — do not edit; regenerate with `nudo contract --emit`
// source: add.js:add2
// derived-from: …/lib.js:add4
import { positive } from "./std.nudo.js";

const x = positive.shift(1);
export const add2 = fn({ x }, x.shift(2));
```

## 检查

```bash
pnpm run check docs/examples/interface-derivation/lib.js
```

根契约 `add4 = fn({ x: positive }, positive4)` 已加载（`pnpm run contract docs/examples/interface-derivation/lib.js`
打印 `add4 [handwritten] …`）；check signatures 当前仍接近原始推断
`add4(x: number) => number | string`——`add2` 的跨文件返回契约
（`add.nudo.js` 的 `x.shift(2)`）尚未回灌到 `add4` 返回位，故
`positive4` 返回位对账为 fail-open（仅可证违例才报错，如字面量 `5` 对 `>10`）。

下游契约的执法看 `add.js`：

```bash
pnpm run check docs/examples/interface-derivation/add.js
```

```
signatures
  add2(x: number) => number
```

（需要 term/pred/conf 细节时用 `pnpm run check … --verbose` 或 `--abs`。）

`add.nudo.js` 是下行 emit 的持久产物（已提交，可经 `contract --emit` 幂等重生成）；
多调用者 join 只进工件，不回灌本链。
