# 单元测试覆盖反思

## 为什么单元测试没有覆盖到这些 Bug？

### Bug 1: 循环累加 (`total += n`)

**根本原因：** 单元测试没有测试复合赋值运算符

**现有测试：**
- 测试了 `total = total + n`（显式赋值）
- 没有测试 `total += n`（复合赋值）

**教训：**
- 复合赋值运算符是常见语法，应该有专门测试
- 应该测试所有赋值运算符：`+=`, `-=`, `*=`, `/=`, `%=`, `**=`, `<<=`, `>>=`, `>>>=`, `&=`, `|=`, `^=`

**修复建议：**
```typescript
describe("Compound assignment operators", () => {
  it("+=", () => { ... });
  it("-=", () => { ... });
  it("*=", () => { ... });
  // ...
});
```

### Bug 2: Promise 双重包装

**根本原因：** 单元测试没有测试 async 函数返回 Promise

**现有测试：**
- 测试了 `async function` 返回字面量
- 测试了 `Promise.resolve(x)`
- 没有测试 `async function` 返回 `Promise.resolve(x)`

**教训：**
- async/await 是常见模式，应该测试所有组合
- 应该测试：
  - `async function` 返回字面量
  - `async function` 返回 Promise
  - `async function` 返回 `await Promise`
  - `async function` 返回 `Promise.resolve(x)`

**修复建议：**
```typescript
describe("Async function return values", () => {
  it("returns literal", () => { ... });
  it("returns Promise", () => { ... });
  it("returns Promise.resolve", () => { ... });
  it("returns await", () => { ... });
});
```

### Bug 3: 对象方法识别

**根本原因：** 单元测试没有测试对象方法语法

**现有测试：**
- 测试了对象属性：`{ key: value }`
- 没有测试对象方法：`{ method() { ... } }`

**教训：**
- 对象方法是 ES6 常见语法，应该有专门测试
- 应该测试：
  - 箭头函数属性：`{ method: () => {} }`
  - 方法简写：`{ method() {} }`
  - 计算属性：`{ [key]() {} }`

**修复建议：**
```typescript
describe("Object methods", () => {
  it("shorthand method", () => { ... });
  it("arrow function property", () => { ... });
  it("computed property", () => { ... });
});
```

## 测试覆盖盲点

### 1. 语法糖覆盖不足

**问题：** 单元测试主要测试了基本语法，没有覆盖语法糖

**例子：**
- `+=` vs `total = total + n`
- `{ method() {} }` vs `{ method: function() {} }`
- `async function` vs `function` + `Promise`

**建议：** 为每种语法糖创建专门的测试用例

### 2. 组合场景覆盖不足

**问题：** 单元测试主要测试了单一功能，没有测试功能组合

**例子：**
- `filter` + `map` + `reduce` 链式调用
- `async function` + `Promise.resolve`
- `Map` + `for...of` + `Array.from`

**建议：** 创建组合场景测试，模拟真实代码

### 3. 边界情况覆盖不足

**问题：** 单元测试主要测试了正常情况，没有测试边界情况

**例子：**
- 空数组的 `reduce`
- 单元素数组的 `filter`
- 嵌套对象的解构

**建议：** 为每种操作创建边界情况测试

### 4. 真实代码模式覆盖不足

**问题：** 单元测试主要测试了简单示例，没有测试真实代码模式

**例子：**
- 数据处理管道
- 错误处理模式
- 事件发射器模式

**建议：** 从真实代码库中提取测试用例

## 总结

**核心问题：** 单元测试覆盖了基本功能，但没有覆盖语法糖、组合场景和边界情况

**根本原因：**
1. 测试设计时没有考虑所有语法变体
2. 测试设计时没有考虑功能组合
3. 测试设计时没有考虑真实代码模式

**改进方向：**
1. 补充语法糖测试
2. 补充组合场景测试
3. 补充边界情况测试
4. 补充真实代码模式测试
